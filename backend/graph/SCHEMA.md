# Threat Hunting Graph Schema (Synthetic Topology)

## Important Design Decision: Synthetic Host Hashing
Because the NSL-KDD dataset lacks real IP addresses or explicit network topology, we synthesize a deterministic "host identity" for each event. This allows us to group related events into "Hosts" and establish `COMMUNICATES_WITH` edges to construct a network graph suitable for downstream GNN (Graph Neural Network) analysis.

### Synthetic Hash Strategy
- **Source Host ID:** A SHA-256 hash of `(protocol_type, service, dst_host_srv_count bucketed into 10 ranges)`.
- **Destination Host ID:** A SHA-256 hash of `(service, flag, dst_host_count bucketed into 10 ranges)`.

This asymmetric derivation ensures the source and destination are rarely identical for the same event, allowing meaningful directional edges.

---

## Graph Schema

### Nodes
1. **`Host`**
   Represents a synthetic machine on the network.
   - `host_id` (String, PK): The synthetic SHA-256 hash.
   - `first_seen` (DateTime): The earliest event time attributed to this host.
   - `event_count` (Integer): Running total of events generated by this host.

2. **`Event`**
   Represents a single network transaction or connection attempt.
   - `event_id` (String, PK): Matches the Postgres `network_event.event_id`.
   - `label` (String): The true attack category (or 'normal').
   - `is_attack` (Integer): 1 if attack, 0 if normal.
   - `risk_score` (Float, Nullable): Populated from the `anomaly_detection_result` table if evaluated.

### Relationships
1. **`(Host)-[:GENERATED]->(Event)`**
   Indicates that a host originated a specific network event.
   - *No additional properties.*

2. **`(Host)-[:COMMUNICATES_WITH]->(Host)`**
   An inferred edge between a synthetic source host and a synthetic destination host.
   - `weight` (Integer): The count of occurrences connecting these two specific synthetic identities.
